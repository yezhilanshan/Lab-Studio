# Five-screen research studio · 2026-11-08

The user chose five primary screens: overview, research progress, topic map, literature timeline and paper-card library. The three related-work views share the same durable paper records. Previous experiment, calibration, comparison and weekly records remain accessible through the research-progress evidence tab and overview links.

The progress tree starts with six roots, grouped stages and the 73 source-grounded research nodes (91 records including roots/stages). Users can add, edit, reparent, fold and soft-delete nodes. The server validates parent presence, same-idea membership and cycles against the merged seed/database graph. Deleting a parent with children requires moving them first. Static defaults remain subordinate to durable user overrides and deletions.

Literature imports 28 cards from the existing local skeleton-supervision review, with five reading dimensions, source/limitations notes and selected cross-paper relationships. These are local-note excerpts, not a fresh literature search or new claims of replication. Missing publication years remain explicitly undated. Users can update themes, year, the five dimensions, private notes, reading status and links to another work.

PDF, DOCX, TXT and Markdown originals (up to 15MB) use the existing private site's R2 binding BUCKET. Document metadata and extracted text are recorded in D1. Downloaded originals use attachment disposition. Text extraction happens in the browser with local PDF.js and Mammoth assets; no CDN dependency. Scan-only PDFs require OCR or manual text. The card stores at most 250000 characters; the summary call sends at most the first 120000 and discloses this in the UI.

The optional summary provider uses an owner-entered public HTTPS Chat Completions-compatible endpoint, model and per-page-memory API key. Keys are not persisted in D1, browser storage, source or error responses. Provider redirects are disabled. Five-dimensional JSON output is validated. Generated content stays in a draft until applied; applying changes the five dimensions and reading status, retaining the user's notes and original text. It records the model and generation time. Existing API key retrieval was not requested; none was obtained. Actual provider quality, credentials, quotas and model availability require the owner's configuration.

Validation: TypeScript and production build; graph cycle/orphan/idea checks; summary URL, missing-key, valid-JSON, malformed-output and provider-error tests with mocked fetch. Browser verified exactly five navigation entries, topic counts and relationships, chronological year groups, adding a tree node with persistence after refresh, and PDF/DOCX/TXT uploads with real local text extraction. Mocked UI summary generation applied all five fields and preserved the original user note; saved fields were read back. Original PDF download returned 200 and matched SHA256. Test fixtures were soft-deleted from local paper records; no local runtime data is packaged. Timeline and topic views had no 390px page overflow; desktop and mobile screenshots were visually inspected.

Real paid provider calls were not made. Deployment preserves owner-private audience, existing records, original research directories and original architecture sources. No database schema migration was required.
