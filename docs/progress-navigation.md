# 研究推进页的信息架构（2026-11-11）

## 问题

原来顶部是三个平级按钮：`整体架构 / 实验进度树 / 历史证据`。但三者并不平级——前两个是「每个想法各有一份」，最后一个是「六个想法合起来的统一编年」。放在同一排会让人以为历史证据也属于当前想法；而且 `整体架构` 视图内部还自带一套 6 个想法的选择卡，和页面上方的 6 个想法卡重复。页面顶部还同时存在 `研究推进`（页面标题）与 `研究推进`（studio 自绘标题）两份标题。

## 现在的结构

三级，范围 → 想法 → 视图：

1. **范围**（二选一）
   - `想法路线`——6 个想法，各自有整体架构与实验进度树。
   - `历史证据`——跨想法统一编年，73 步记录与挂接原文。
   - 两卡右侧有一句对照说明：想法路线看「为什么这样做」，历史证据看「按什么顺序做」。
2. **想法**（仅想法路线下出现）：6 个紧凑卡，编号 + 名称 + 状态，当前项左侧竖条 + 底色。
3. **视图**（仅想法路线下出现）：`整体架构 / 实验进度树` 分段切换，右侧一行上下文（进度树提示"右键主题可跳到该步在历史证据中的位置"，架构显示想法编号与状态）。

历史证据范围下，原来的「旧版记录」四个入口降级为一行文字链，位于范围卡与编年线之间。

## 相关改动

- `app/studio.tsx`：`scope`（ideas/evidence）与 `view`（architecture/tree）两个状态；`openEvidence` 只切范围，`locateInTree` 切回范围 + 视图 + 想法；删除自绘 hero。
- `app/ideas.tsx`：`IdeaCatalog` 新增 `embedded`，嵌入时隐藏自身的选择卡与导语，只保留「下载六张架构图」链接。
- `app/desk.css`：`.studio-scope` / `.studio-ideas` / `.studio-viewbar` / `.studio-legacy-links` / `.idea-catalog.is-embedded`；≤1100px 想法卡转 3 列并隐藏右侧说明，≤640px 转 2 列、范围卡纵向堆叠。

## 验证

- 三态截图（进度树 / 架构 / 证据）与 1280、390 宽度检查，横向溢出 0；390 下范围卡堆叠、想法卡 2 列。
- 双向跳转在新结构下仍成立：树右键「在历史证据中查看」→ 范围切到历史证据并定位到该步；证据卡「在实验进度树中定位」→ 范围切回想法路线、视图切到进度树、选中主题并提示。
- `tsc`、`eslint app/studio.tsx app/ideas.tsx`、`check-studio`、`check-mindmap` 通过。

## 视觉层（2026-11-11 晚）

第一版结构对了但视觉仍像表单：两排"白底细边框盒子"（2 个范围卡 + 6 个想法卡）权重相同，选中态是几乎看不出差别的淡绿，每张想法卡下面还挂一行 9px 灰字。第二版改成版式化处理：

- **范围**：换成深松绿胶囊分段控件（选中项实底反白），右侧一行说明当前范围的含义；不再用大卡片。
- **想法**：改成目录条——上下各一条细线，六项之间用竖分隔线，编号用衬线小号，选中项顶部 2px 松绿压条 + 文字加深；每个想法的状态收成 5px 圆点（绿=有实验/已评估，赭=待验证，砖红=No-Go），完整状态文字放在 `title` 里。
- **视图**：从方块按钮改为下划线式文字页签；右侧由视图决定——进度树显示"右键可跳证据"的提示，整体架构显示「下载六张架构图」。
- **画布标题栏**：去掉输入框边框，标题用衬线体当文档标题；状态改成 10px 等宽小字；「保存」改为实底主按钮。
- **编年线**：章节标题从 26px 降到 17px（页面已有大标题，避免两个标题打架），月份从带框按钮改为文字链接，筛选下拉去掉浏览器原生外观统一为纸面样式。

注意两个全局样式的坑：`nav { flex-direction: column }` 会把任何 `<nav>` 变成竖排（想法条因此改用 `div role="group"`），`dt { margin: 17px 0 6px }` 会把小标签压到下一行。

## 画布取景（同日追加）

进度树整棵树（idea3 有 41 个节点）在 `fit()` 到整个画布时会被缩到 0.12 倍，文字不可读、四周大片空白。现在实验树的画布打开时改为**把根主题居中、缩放 0.6**，读者从根出发沿分支展开；独立主题画布仍保持整图适配。`.simple-map-editor` 在进度树里改用 `clamp(440px, 100dvh - 505px, 880px)`，避免画布比首屏还长、下方多出一截空白。

取景必须在 `ready` 之后执行（首帧 `api` 还没挂上），并且只做一次——用 `framed` ref 保证"专注画布"切换等重渲染不会把用户的平移重置。
