# Radar-to-Text MVP 验证全过程复盘

时间范围：2026年9月中旬—2026年10月11日，重点回顾10月10日至11日完成的离线 MVP 实验

截至目前，你已经完成了一条比较完整的验证链：

**MVP 架构实现 → 首轮训练 → 系统性错误归因 → 分类头受控消融 → 强分类基线 → 同编码器公平对照 → 动作证据探针 → 时序解码和数量校准**

整个过程最重要的变化是：

最初你证明了毫米波信号能够驱动冻结 LLM 生成有序动作描述；随后发现原始分类基线过弱；进一步验证后，强分类与时序解码已经能够在现有任务上达到甚至略微超过 LLM 的性能。

因此，MVP 的工程可行性获得了初步验证，但其语言模型路线的独特优势仍未得到充分证明。

## 一、整个实验经历了哪些阶段？

| 阶段 | 主要工作 |
| --- | --- |
| 准备（阶段0） | 研究目标收缩、PARrad 适配、MVP 实现 |
| Pilot（阶段1） | Stage 1 预训练 + Align，跑通 Radar-to-Text |
| 归因（阶段2） | 逐帧混淆、冻结特征探针、无雷达/时间扰动 |

| P0（阶段5） | 固定 Align Encoder，公平比较两条读出流程 |
| P1（阶段6） | H/Z/P 探针、编辑错误分解、HMM 与 Count-Viterbi |

这些实验主要集中在10月10日至11日。此前9月29日至10月9日的流式事件检测、Fork-and-Shadow、分层记忆等实验属于上一套研究方案，已有单独复盘，不应将它们的指标与当前离线 MVP 混用。

## 二、阶段0：确定 MVP 的研究目标与实验设计

### 1. 为什么要构建这个 MVP？

你原来的研究方案较复杂，涉及连续事件检测、语义变化判断、候选确认、分层记忆以及 LLM 推理。

但这些模块同时存在时，很难回答最基础的问题：

毫米波雷达特征能否直接作为 LLM 的输入，使其生成具有正确时间顺序的动作描述？

因此，在2026年10月10日，你将目标收缩为：

> 给定一段连续毫米波雷达数据，离线生成其中人体行为的有序自然语言描述。

暂时不研究实时处理、事件边界检测、流式记忆和复杂推理。

### 2. 选择 PARrad 作为验证数据集

PARrad 提供两种输入：

| 输入                      | 内容        | 当前用途           |
| ----------------------- | --------- | -------------- |
| Range-Doppler Map       | 距离与径向速度分布 | 提取人体整体运动信息     |
| Micro-Doppler Signature | 微多普勒频谱    | 提取局部时间范围内的运动特征 |

数据集包含14类动作，例如：

`walks toward the bed → gets into bed → lies in bed`

你最初先检查了少量 PARrad 记录及标签格式，随后在当前 MVP 中使用了5名受试者。

固定受试者划分：

| 集合         | 受试者             |
| ---------- | --------------- |
| Train      | subject02、03、04 |
| Validation | subject05       |
| Test       | subject06       |

实验窗口：

| 参数            | 设置    |
| ------------- | ----- |
| 窗口长度          | 12秒   |
| 滑动步长          | 6秒    |
| 最短有效窗口        | 8秒    |
| GT 动作段数量      | 不超过3  |
| Train 窗口      | 2,187 |
| Validation 窗口 | 702   |
| Test 窗口       | 484   |

后续为了更加严格地比较，又排除了 Validation/Test 中各2个不足12秒的尾窗，采用700/482个完整名义12秒窗口作为主要评价集合。

这里埋下了第一个研究限制：窗口根据真实标签筛选，绝大多数包含3个动作，并不代表任意长度、不定动作数量的真实连续雷达流。

### 3. 弱标签和自然语言监督

PARrad 当前使用的标签策略是：

`command_active_until_next_command`

即动作指令标签持续到下一条指令出现。

你利用类别名称自动生成英文描述模板，例如：

“The person walks toward the bed, then gets into bed, and then lies in bed.”

这样无需人工编写大量 Caption，就可以得到 Radar-to-Text 训练数据。

但这些标签只能监督动作类别、实例数量和顺序，不能可靠监督真实动作执行边界、运动幅度、停顿等细节。

## 三、阶段1：实现并首次训练 Radar-to-Text MVP

### 1. 网络架构

最终采用了一个相对轻量的双分支模型，整体数据流为：

`RD/MD → 双 CNN → BiGRU → 8 个有序 Radar Tokens → Projector → 冻结 Qwen → 文本`

| 模块 | 输入 | 结构 | 输出 |
| --- | --- | --- | --- |
| RD 分支（RD CNN） | 逐帧距离-多普勒图（RD Maps） | 3 层 Conv2D（32→64→128）+ 全局平均池化 | 128D |
| MD 分支（MD CNN） | 局部时间-频率切片（MD Signature） | 3 层 Conv2D（32→64→128）+ 全局平均池化 | 128D |
| 特征拼接 | 两分支特征 Concat | 拼接为 256D | 256D |
| 时序编码 | 256D 逐帧特征序列 | 2 层双向 GRU | 每个时间步 256D |
| 时间池化 | 完整时间序列 | Adaptive Temporal Average Pooling | 8 个有序 Radar Tokens |
| MLP Projector | 8×256 Radar Tokens | 256 → 896 → 896 | 8×896 |
| Frozen Qwen2.5-0.5B-Instruct | Soft Radar Prefix + 文本指令 | 冻结参数，自回归生成 | 动作描述文本 |

### 2. 两阶段训练

**Stage 1：雷达分类预训练**

利用逐帧14类分类任务训练：

`RD/MD CNN → BiGRU → Linear(256,14)`

训练3个 Epoch，最佳检查点为 Epoch 2。

目的：让雷达编码器先学习基本动作特征。

**Stage 2：Radar-to-Language Alignment**

加载 Stage 1 编码器权重，训练 Radar Encoder 和 Projector，使其输出能够被冻结 Qwen 读取。

训练3个 Epoch，最佳检查点为 Epoch 3。

损失函数采用自然语言自回归 Cross-Entropy，只监督目标文本部分。

这一步没有训练 Qwen 主体，也没有进行 LoRA。

### 3. 第一次 Pilot 的结果

| 方法                   | Test 完整序列正确率 |
| -------------------- | ------------ |
| 原 Stage 1 分类头 + 模板   | 11.16%       |
| Radar-to-Text + Qwen | 25.00%       |

原协议共484个测试窗口，Qwen 预测正确121个。

同时：

| 指标               | Qwen    |
| ---------------- | ------- |
| Action Precision | 50.72%  |
| Action Recall    | 46.28%  |
| Order LCS        | 45.59%  |
| 预测动作数量偏少         | 148/484 |

当时的初步结论：

MVP 已经能够运行，真实雷达输入可以驱动冻结 LLM 生成动作描述，而且完整序列指标明显超过原分类模板。

但这时还不能确定优势究竟来自语言模型，还是因为分类基线过弱。

## 四、阶段2：系统性错误归因

2026年10月11日，六阶段诊断

这是第一次从“模型能不能运行”转向“为什么性能不够好”。

### 1. 检查原 Stage 1 分类能力

| 数据         | Frame Macro-F1 |
| ---------- | -------------- |
| Train      | 34.82%         |
| Validation | 29.50%         |
| Test       | 34.62%         |

原分类头的表现本身就不理想。

尤其是床相关类别：

- `gets into bed`：Validation F1 8.93%。
- `stands up from the bed`：9.22%。
- `sits down on the bed`：13.48%。

随后，你将标签转换点前后各0.3秒排除，再计算稳态帧准确率。

结果 Validation Macro-F1 仅从29.50%提高到30.26%。

结论：错误不是简单地由动作边界标签不准确引起的；稳定标签区间内的类别区分也存在明显不足。

### 2. 冻结特征探针

你冻结已有 Stage 1 和 Align 编码器，提取 CNN 与 BiGRU 特征，仅重新训练线性分类头。

| 特征           | Validation Macro-F1 | Test Macro-F1 |
| ------------ | ------------------- | ------------- |
| Stage1 CNN   | 18.80%              | 17.96%        |
| Stage1 BiGRU | 47.47%              | 49.15%        |
| Align CNN    | 19.98%              | 18.94%        |
| Align BiGRU  | 50.55%              | 51.44%        |

这次得到了三个发现：

第一，BiGRU 特征比单独 CNN 融合特征更容易被线性分类头读取。

第二，Align 后没有出现整体类别可读性退化，反而略有提高。

第三，原 Stage 1 分类头的29.50%明显低于重新训练读出器的47.47%，说明问题不一定全部来自编码器。

因此，研究重心开始从“直接改 CNN”转向“检查训练与读出”。

### 3. 判断 Qwen 是否真正使用雷达

你开展了三类对照。

| 实验          | 结果               |
| ----------- | ---------------- |
| 固定前缀无雷达模型   | Test Exact 1.24% |
| 训练集众数静态句    | 9.09%            |
| 真实雷达 + Qwen | 25.00%           |

同时，进行了真实雷达与错配雷达的对照。

Validation 和 Test 各64组，其中各61组的正确雷达输入具有更低的目标文本 Loss。

将 RD/MD 同步进行时间打乱后，测试子集完整序列准确率从23.44%降到1.56%。

结论：模型确实利用了雷达输入，对时间结构也具有敏感性。

但时间打乱属于分布外扰动，不能单独证明模型正确理解了动作先后顺序。

真实反序动作配对实验同样没有得到足以隔离纯顺序理解能力的证据。

### 4. 发现动作覆盖问题

测试集共包含1,358个真实动作实例，其中736个没有被生成文本的类别多重集覆盖：

未覆盖率54.20%。

进一步按窗口位置和截断情况分析：

| 条件      | Test 未覆盖率 |
| ------- | --------- |
| 窗口开头    | 48.53%    |
| 窗口中间    | 45.88%    |
| 窗口结尾    | 65.45%    |
| 完整落在窗口内 | 47.83%    |
| 右侧截断    | 64.66%    |

这提示生成模型存在明显的末端动作覆盖不足现象。

但这种未覆盖还混合了类别替代、重复实例匹配等错误，不应全部解释为模型完全没有检测到动作。

此外，测试中可见时长不足1秒的102个动作实例全部来自窗口截断，并不代表真正短动作。

### 5. 这一阶段的最终判断

问题同时存在于：

- 雷达类别判别；
- 原分类头训练；
- 动作覆盖；
- 生成数量和顺序；
- 弱标签及窗口截断。

因此不能简单将错误归因于 Projector 或 Qwen。

## 五、阶段3：H0–H4 分类头受控消融

这是为了回答：

原 Stage 1 分类头为什么这么差？

你冻结最终的 Stage 1 Encoder，仅训练3598个分类头参数。

设计五种训练配置：

| 方法 | 额外训练 Epoch | 类别加权 | 特征标准化 |
| -- | ---------- | ---- | ----- |
| H0 | 3          | 否    | 否     |
| H1 | 20         | 否    | 否     |
| H2 | 3          | 是    | 否     |
| H3 | 3          | 否    | 是     |
| H4 | 20         | 是    | 是     |

同时做了 original_optimizer 和 probe_replay 两组实验，避免仅靠一组新训练结果解释原分类头的问题。

original_optimizer 组的结果：

| 方法                    | Val Macro-F1 | Test Macro-F1 |
| --------------------- | ------------ | ------------- |
| 原 Stage 1 Head（H0@0） | 29.50%       | 34.62%        |
| H0                    | 43.03%       | 45.35%        |
| H1                    | 45.65%       | 49.28%        |
| H2                    | 45.13%       | 45.38%        |
| H3                    | 43.52%       | 46.80%        |
| H4                    | 47.67%       | 49.42%        |

最重要的发现是：

即使不更新 CNN 和 BiGRU，只重新训练最终分类头，也可以获得显著更好的逐帧 Macro-F1。

但不能将 H0@0 到 H0@3 的差异完全归因于原训练 Epoch 不够，因为冻结特征训练和最初联合训练的样本上下文、采样及优化器状态不完全相同。

这一轮之后，你决定用 H1/H4 建立更强的分类序列基线，而不是直接修改 Encoder。

## 六、阶段4：H1/H4 强分类模板与 Qwen 同窗口比较

这一阶段解决一个重要公平性问题：

之前11.16%的分类基线是否过弱，从而夸大了25%的 Radar-to-Text 优势？

你重新执行 Stage 1 时序编码，让分类路径与 Qwen 路径使用完全相同的原始 RD/MD 窗口。

分类路径：

`Stage 1 Encoder → H1/H4 → 平滑 → 模板`

语言路径：

`Align Encoder → Projector → Qwen`

所有方法共享相同窗口、时间戳、标签和评价规则。

### 严格482个完整测试窗口结果

| 方法               | Sequence Exact | Action Recall |
| ---------------- | -------------- | ------------- |
| B0：原 Stage1 + 模板 | 11.83%         | 49.03%        |
| B1：Stage1 + H1   | 17.84%         | 60.06%        |
| B2：Stage1 + H4   | 18.05%         | 60.10%        |
| B3：Align + Qwen  | 24.69%         | 46.06%        |

B3 仍然领先 Validation 选出的 B1 6.85个百分点。

但优势已经从原来的约13个百分点缩小到约7个百分点。

### 发现了两种不同的错误倾向

B1 平均每窗口输出3.72个动作，偏向冗余预测。

B3 平均每窗口输出2.52个动作，偏向保守输出。

分类方法 Recall 更高，但额外预测动作较多；Qwen 的完整序列准确率更高，却经常没有覆盖全部类别。

这一轮结论：初始分类基线确实过弱，但在不同 Encoder 的条件下，Qwen 完整序列优势仍然存在。

这促成了下一轮 P0 同编码器实验。

## 七、阶段5：P0——冻结同一个 Align Encoder 的公平对照

你这次固定了完全相同的 Align Encoder：

- 一条路线接新训练的 H1/H4 分类头。
- 另一条路线保留原 Projector 和 Qwen。

Encoder 参数全部冻结。

### 结果

| 方法           | Sequence Exact | Recall | Count MAE |
| ------------ | -------------- | ------ | --------- |
| Stage1 + H1  | 17.84%         | 60.06% | 1.141     |
| Align + H1   | 18.88%         | 65.91% | 1.098     |
| Align + H4   | 18.67%         | 64.18% | 1.093     |
| Align + Qwen | 24.69%         | 46.06% | 0.336     |

### 发现1：Align Encoder 没有破坏类别信息

在相同非重叠上下文的 H1 读出实验中：

Test Macro-F1 从49.28%提高至51.74%。

这说明语义对齐后的编码器，至少在当前配方下仍保留了可读的动作类别信息。

### 发现2：分类与语言读出的错误结构不同

在482个完整窗口中：

| 统计     | Align + H1 | Align + Qwen |
| ------ | ---------- | ------------ |
| 动作数量正确 | 172        | 321          |
| 数量偏多   | 253        | 13           |
| 数量偏少   | 57         | 148          |

这次发现非常重要：

Qwen 在预测动作数量方面明显优于原分类流程，但它并不一定能识别正确的动作类别。

比如：

| 动作                     | Align H1 Recall | Qwen Recall |
| ---------------------- | --------------- | ----------- |
| gets into bed          | 74.39%          | 17.07%      |
| gets out of bed        | 66.67%          | 8.33%       |
| lies in bed            | 58.33%          | 11.67%      |
| stands up from the bed | 66.67%          | 22.22%      |

这提示同一个 BiGRU Encoder 的输出包含一些可以读出的床相关类别信息，但当前 Qwen 完整生成路径未能充分表达。

不过，因为分类路径使用完整逐帧 BiGRU 特征，而 Qwen 使用8个压缩 Token，尚不能判断是哪一层造成差异。

## 八、阶段6：P1——动作证据保留与数量校准诊断

这是截至目前最新、也是对研究结论影响最大的一轮实验。

它分成 P1-A、P1-B、P1-C。

### P1-A：精确分解序列错误

首先重新计算：

- 动作数量正确率。
- Count MAE。
- Levenshtein 编辑距离。
- 插入、删除、替换错误。
- B1 与 B3 的逐窗口配对差异。

结果：

| 指标             | Align + H1 | Align + Qwen |
| -------------- | ---------- | ------------ |
| Sequence Exact | 18.88%     | 24.69%       |
| 数量正确率          | 35.68%     | 66.60%       |
| 平均编辑距离         | 2.037      | 1.606        |
| 插入次数           | 476        | 19           |
| 删除次数           | 63         | 155          |
| 替换次数           | 443        | 600          |

这里明确发现：

分类路线更容易出现冗余动作，而 Qwen 的删除和类别替换错误较多。

但不能将分类错误全部归因于插入，也不能认为 Qwen 全部是漏动作。

你还检查了29个分类独对窗口和57个 Qwen 独对窗口，发现两者都存在类别替换与复杂混合错误。

### P1-B：H → Z → P 动作信息探针

这是为了验证此前的架构假设：

8个均匀时间池化 Token 是否损失了动作顺序信息？

定义三个位置：

- H：完整 BiGRU 输出，T×256。
- Z：平均池化后的8×256 Radar Tokens。
- P：Projector 后的8×896特征。

对每个位置训练线性/非线性探针，预测动作存在性、数量和有序动作序列。

**P1-B：有序动作序列探针结果**（Test Ordered Sequence Exact，采用相应非线性探针）：

| 探针位置 | Ordered Sequence Exact |
| --- | --- |
| H：BiGRU 完整输出（T×256） | 21.16% |
| Z：8 个 Radar Tokens（8×256） | 25.31% |
| P：Projector 输出（8×896） | 21.16% |

得到两个发现。

首先，Z 并没有比 H 差。

Z 的有序动作序列预测达到25.31%，H 为21.16%。

这不支持“8个均匀池化 Token 是当前主要信息瓶颈”的简单假设。

当然，两者输入维度和探针参数规模不同，不能据此证明池化一定更优。

其次，P 的有序动作可读性低于 Z。

Z 为25.31%，P 为21.16%。

但是 P 的动作存在性 F1 与 Z 相近，因此这种差异更值得从动作组合与顺序角度检查。

目前只能说 Projector 后的有序动作信息在现有探针下更难读取，不能断言其不可逆地丢失。

这一结果直接改变了架构决策：

暂时不优先引入 Event Queries、Hungarian Matching 或增加 Radar Token 数量。

### P1-C：更强的分类时序解码

这是最关键的结果。

你开始针对分类输出冗余严重的问题改进后处理。

依次测试：

1. 概率平滑与最短动作段过滤。
2. 基于训练集转移先验的 HMM/Viterbi。
3. 独立动作数量预测头。
4. 预测数量约束下的 Segment Viterbi。

所有正式参数通过 Validation 选择。

#### 最终结果

P1-C：时序解码改进后的完整序列准确率（严格482个测试窗口；Oracle 使用真实数量，仅作为诊断）

详细比较：

| 方法             | Exact  | Recall | Count MAE |
| -------------- | ------ | ------ | --------- |
| Align H1 + 原平滑 | 18.88% | 65.91% | 1.098     |
| Align + Qwen   | 24.69% | 46.06% | 0.336     |
| 概率/最短段过滤       | 20.54% | 58.71% | 0.624     |
| HMM            | 25.52% | 59.13% | 0.413     |
| 预测数量 + Viterbi | 27.18% | 57.68% | 0.216     |
| Oracle 真实数量    | 34.02% | 59.82% | 0         |

这是整个 MVP 实验的关键转折点。

强化分类路径之后，首次在完整序列指标上超过了直接 Radar-to-Text。

而且不依赖额外 Count Head 的 HMM 已经达到25.52%，略微超过 Qwen 的24.69%。

因此，之前“LLM 具有更强的动作序列恢复能力”的解释已经不再成立。

### P1 还揭示了数据数量先验问题

严格482个 Test 窗口中：

| 真实动作数量 | 窗口数 |
| ------ | --- |
| 1      | 2   |
| 2      | 90  |
| 3      | 390 |

也就是说，80.91%的测试窗口包含3个动作。

永远预测3个动作，数量准确率就能达到80.91%。

而 Count Head 的数量准确率为78.63%。

因此，高数量准确率本身不证明模型理解了实际动作数量。

不过，在同一解码器下：

- 固定 K=3：Sequence Exact 24.07%。
- 预测 Count：27.18%。

说明预测数量仍然对最终序列有一定帮助，但这种收益需要新的受试者和更平衡的动作数量分布进行确认。

## 十一、截至目前，MVP 到底验证成功了什么？

我建议将整个 MVP 的验证结论分为四个层次。

### 1. 工程可行性：已经验证

你已经实现并验证了：

`RD/MD → 双 CNN → BiGRU → Radar Tokens → Projector → 冻结 Qwen → 文本`

同时完成两阶段训练、Checkpoint 恢复、跨受试者数据划分、雷达输入推理、批量生成和指标计算。

各轮还进行了输入摘要、权重 SHA、源代码和逐窗口结果复核。

因此，从工程角度看，MVP 是跑通的。

### 2. 雷达内容确实能够影响生成：初步验证

真实雷达模型明显优于已测试的无雷达对照。

正确雷达与文本的匹配 Loss 多数低于错配输入。

所以模型并非完全忽略雷达，而只是根据语言模型先验随意生成。

但是尚未量化它究竟理解了多少动作细节和顺序关系。

### 3. 连续动作序列理解能力：尚未充分验证

目前最强可部署方法的完整序列准确率只有27.18%。

即使提供真实动作数量，固定解码器也只有34.02%。

而 Qwen 的完整序列准确率为24.69%，存在明显类别遗漏、替换和末端覆盖不足。

这些结果还不能充分支持“可靠的连续多动作理解”。

### 4. LLM 相对于传统时序识别的独特价值：尚未验证

当前数据的文本主要来源于14个固定动作类别。

因此，传统分类器同样可以恢复这些类别，再通过模板生成文本。

现有实验还没有充分验证：

- 细粒度运动属性描述；
- 可变长度的连续动作生成；
- 超过3个动作的长期时间关系；
- 基于雷达的复杂问答；
- 可靠的开放式语言描述。

这些才是你原始研究目标中需要进一步完成的内容。

## 十三、我对这段 MVP 验证经历的整体评价

我认为，这一过程可以概括成三个研究转折。

第一次转折：从“模型跑通”到“模型是否真的使用雷达”。

你通过无雷达先验、错配和时间扰动，初步证明了模型利用输入信号，但没有将这一结果过度解释成可靠顺序理解。

第二次转折：从“LLM 比分类器好”到“原始分类器其实不够强”。

你通过冻结头消融、H1/H4 和同编码器 P0，逐步排除了原始分类器训练不足及编码器差异的干扰。

第三次转折：从“该改 Radar Tokens 或 Projector”到“现有任务本身可能不足以体现 LLM 价值”。

P1 发现8个均匀池化 Token 并没有明显限制有序动作探针表现，而 HMM/Count-Viterbi 可以通过结构化时序解码达到更高准确率。

这意味着下一步不应仅围绕“怎么让 Qwen 把14类动作名称输出得更准确”展开，而应重新明确 LLM 在连续毫米波行为理解中到底负责哪些传统时序解码难以完成的能力。

## 最终总结

如果要将目前的 MVP 实验写成一段研究进展，我建议这样表述：

> 本研究首先构建了一个基于双分支 CNN、双向 GRU、固定数量有序 Radar Tokens 和冻结语言模型的离线毫米波行为描述 MVP，并在 PARrad 数据集上完成初步跨受试者验证。随后，通过逐帧类别混淆分析、冻结特征探针、分类头训练消融、雷达错配实验和动作覆盖分析，确认了原始分类读出的训练不足及直接语言生成路径中的类别遗漏问题。在统一窗口和同编码器条件下，逐步建立了更强的分类基线，并进一步引入概率后处理、动作转移先验和预测数量约束。最终，预测数量与 Segment Viterbi 组合在现有测试协议下取得27.18%的完整动作序列准确率，略高于直接 Radar-to-Text 的24.69%。与此同时，H/Z/P特征探针未发现固定时间池化导致的明确整体退化，但显示 Projector 后的有序动作序列可读性存在下降迹象。上述结果表明，当前 MVP 已初步验证毫米波与冻结语言模型对齐生成的技术可行性，但仍不足以证明 LLM 在固定类别动作序列恢复方面优于强结构化时序解码方法。后续研究需要通过更大规模的受试者验证、可靠物理属性监督和可变长度连续描述任务，进一步探索语言模型的独特作用。

一句话概括整个过程：你已经从“验证毫米波能否接入 LLM”，走到了“通过严格对照明确 LLM 在毫米波连续行为理解中究竟需要解决什么问题”。

这也是目前最有价值的阶段性成果：不仅建立了一个可运行的 MVP，还通过连续实验确定了它的能力边界、主要错误结构，以及下一阶段真正需要突破的研究问题。
