先说结论：这个领域已经收敛到几条路线，而且我之前提的三个想法，大多已经有人做了。

**一、现有工作怎么让 LLM 读懂雷达**

- 连续特征加投影器（最主流）：mmMind 用同步的三维姿态做训练期的监督，再把学到的雷达表示对齐到 LLM，用于行为描述和时空问答。它还指出，过早做离散量化可能在语言对齐之前就形成信息瓶颈。另有一个对你很实用的发现：雷达接冻结视觉语言模型时，主要失败原因是 token 范数不匹配，在投影器输出加 LayerNorm 就能解决。你的冻结 Qwen 路线正好用得上。
- 离散雷达 token：RadarLLM 用运动引导的 VQ-VAE 把点云序列变成语义 token，并用物理感知的合成流程，从"动作-文本"数据集生成雷达-文本配对数据。这等于我之前"雷达词典"想法的前身。
- 把雷达写成文字：mmWave-QA 把点云转成坐标文本，让现成 LLM 零样本推理。Wi-Fi 方向也有类似做法，Wi-Chat 把感知的物理原理写进提示，让 LLM 直接读原始 CSI。
- 证据与智能体：有一篇免训练的毫米波动作识别工作，把识别改成基于证据的推理，用检索加证据组装完成。
- 拿视频或文本当"老师"：WiFi2Cap 用视频-文本模型做教师，让 CSI 学生去对齐它的视觉和文本空间。WirelessSenseLLM 先用同步视频做对比预对齐，再接 LLM 微调，可以直接处理未分段的 CSI。

**二、连续长流方面已经有什么**

- mmMind 的附录把长录制切成 5 秒片段，每段生成带起止时间的描述存成时序记忆，提问时再检索相关片段重新感知。
- WirelessSenseLLM 主张免分割，让 LLM 在未分段信号上提供自然断点和更长时间跨度的关联。
- 传统雷达连续识别里有个简单技巧：用固定窗口，每个窗口做多标签分类，容纳同一窗口内的多个动作。

据我理解，mmMind 这种固定 5 秒片段的做法，正好留下了你关心的跨片段连续性和长期漂移问题，但这是我基于摘要和附录片段的推断。

**三、其他领域可以借鉴的**

- 传感器 LLM：SensorLLM 给每个传感器通道加特殊 token，并自动生成趋势描述来对齐，不需要人工标注。对应到雷达，可以对距离、多普勒、角度各通道这样做。
- 事件相机（同样是"只记录变化"的传感器）：EventGPT 先用 RGB 图文数据热身，再用合成事件-文本数据训练对齐模块，最后真实数据微调。思路是分阶段、借一个"桥梁模态"，对雷达来说桥梁可以是姿态或动作文本。
- 流式视频 LLM：LiveStarPro 用困惑度验证来决定何时回应，并用层级记忆把被淘汰的历史整理成事件链。Response-G1 则用场景图加检索，再逐帧判断"沉默还是回应"。这些正对应你的"何时说话"和"事件记忆"问题。
- 视频时间定位：Grounded-VideoLLM 把时间戳变成词表里的离散时间 token。VTG-LLM 则加入序列-时间嵌入和绝对时间 token。这能解决"时序化描述"里时间戳不准的问题。
- 时间序列 LLM 的警示：Time-LLM 用文本原型把时间序列重编程后喂给冻结 LLM。但后续研究发现，这类方法的收益更多来自时间序列本身的结构，而非真正的语言对齐，存在"伪对齐"。所以你必须做"去掉 LLM 或换成小模型"的对照实验，证明 LLM 确实有贡献。

**四、我的判断**

1. 单纯"怎么对齐雷达和 LLM"这条路已经很拥挤，要拿新颖性很难。
2. 你的 pilot 里可以立刻试的低成本改动：投影器输出加 LayerNorm。
3. 相对空白的地方可能是：毫米波加在线持续叙事，具体是跨片段连续性、长期记忆，以及日记式输出的漂移与一致性评估。这个"空白"只是我没搜到直接对应的工作，不等于不存在，需要你再确认。
4. 一个务实的拼装路线：编码器对齐沿用现成做法（姿态引导或离散 token），说话时机借鉴流式视频 LLM，时间戳借鉴离散时间 token，贡献放在新的连续评测和漂移分析上。
