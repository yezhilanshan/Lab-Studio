# Radar-to-Text v1.1：毫米波连续动作自然语言描述优化方案

研究方案 · PARrad · 离线训练与推理 · 基于 2026-10-10 Pilot 制定

## 一、研究目标与总体决策

我建议将研究方向正式收敛为：

基于毫米波时序表征与大语言模型的连续人体动作自然语言描述。

暂时不再考虑实时推理、事件边界检测、Fork-and-Shadow、Event Memory 等旧方案模块。

本轮研究围绕三个问题展开：

1. 感知能力： RD/MD 编码器能否准确识别连续雷达信号中的各个动作，尤其是容易混淆、持续时间较短的动作？
    
2. 语义对齐： 如何将雷达时序特征有效传递给 LLM，避免正确的动作信息在跨模态映射中丢失？
    
3. 完整描述： 如何让 LLM 按正确时间顺序描述所有可观察动作，而不是遗漏动作、混淆类别或生成没有雷达依据的内容？

### 1.3 实验原则

本方案采取一条明确路线：

冻结基线 → 诊断错误来源 → 修改一个因素 → 验证收益 → 再进入下一阶段。

不提前假定 Encoder、Projector 或 LLM 哪一个存在问题。所有性能改进都必须能够通过对照实验解释。

## 三、Stage 1：系统性错误归因

复用已有权重，优先不训练大模型

这一阶段最重要，建议优先完成。

### 3.1 雷达编码器分类诊断

首先读取 Stage 1 最佳权重，输出逐帧分类结果。

需要计算：

| 指标               | 意义                 |
| ---------------- | ------------------ |
| Frame Accuracy   | 总体逐帧准确率            |
| Macro-Precision  | 各类别 Precision 的宏平均 |
| Macro-Recall     | 各类别 Recall 的宏平均    |
| Macro-F1         | 各类别 F1 的宏平均        |
| Per-class F1     | 每个动作单独的 F1         |
| Confusion Matrix | 动作间的具体混淆关系         |

这里需要同时报告两种结果：

- 全部有效帧： 保留所有动作标签。
    
- 远离标签转换点的帧： 额外排除转换点前后约 0.3 秒的帧，仅作诊断，不代替完整结果。
    

第二种评价可以帮助判断：模型究竟连动作稳态都无法识别，还是主要在模糊的动作过渡区域出现错误。

重点分析六类动作：

- gets into bed
    
- gets out of bed
    
- lies in bed
    
- stands up from the bed
    
- stands up from the chair
    
- stands up from the floor of the room
    

应当绘制完整 14 类混淆矩阵，避免只根据这六类得出结论。

### 3.2 冻结特征的可分性检查

比较三个位置的特征：

|特征|提取位置|诊断目的|
|---|---|---|
|$F_{\text{CNN}}$|双 CNN 融合之后|原始 RD/MD 是否包含动作区分信息|
|$F_{\text{GRU}}$|BiGRU 输出之后|时间上下文是否帮助识别|
|$F_{\text{Align}}$|Align 后编码器输出|语言对齐是否造成特征退化|

每个特征使用统一规格的线性分类探针，并在训练受试者上拟合、未参与探针训练的验证受试者上评价。

这里要分别比较 Stage 1 和 Align 后的模型，不能只比较网络内部不同层。

最终得到一张表：

|特征|Macro-F1|床相关动作 Macro-F1|短动作 Recall|
|---|---|---|---|
|CNN 融合输出|待测|待测|待测|
|Stage 1 BiGRU|待测|待测|待测|
|Align 后 BiGRU|待测|待测|待测|

诊断判据：

- CNN 特征很差、GRU 特征也差：优先考虑感知编码器。
    
- CNN 特征可分、GRU 退化：重点检查时序编码及预训练。
    
- Stage 1 可分、Align 后退化：重点检查端到端对齐是否损害雷达特征。
    
- Align 后仍然可分，但生成召回差：优先检查 Projector、文本训练目标与 LLM 解码。
    

线性探针只能判断特征是否可被简单读出，不能单独证明 LLM 已经具备同等识别能力。

### 3.3 三组必要对照实验

#### A. 平滑分类模板基线

保留 Stage 1 分类结果，但对连续帧的类别预测进行后处理：

```
Frame logits
    ↓
Argmax / 可选置信度处理
    ↓
Median Filter
    ↓
Minimum Duration Filtering
    ↓
Merge Consecutive Segments
    ↓
Natural Language Template
```

建议先比较下列固定候选：

|参数|候选|
|---|---|
|中值滤波时间窗|0 / 0.3 / 0.5 秒|
|最短动作段长|0 / 0.3 / 0.6 秒|
|相邻同类段合并|启用|
|最终输出动作数|不强制使用真实 GT 个数|

所有阈值只能在训练/验证数据中选择，并依据真实时间戳换算成帧数。

这组基线非常重要，因为你首轮的分类基线没有平滑，容易因为逐帧抖动而输出过多动作。

#### B. 无雷达语言先验

训练一个不接收真实雷达、只使用相同训练集描述文本的语言基线。

推荐使用 8 个可学习的固定前缀 Token + 同一个冻结 Qwen，训练监督和解码配置保持一致。

目的：衡量 Qwen 在没有雷达证据时，单靠训练集常见动作序列能够预测到什么程度。

这样比直接把雷达 Token 置零更合理，因为置零可能使模型接收到训练时从未出现过的输入。

#### C. 雷达错配与时间信息破坏

分成两种诊断，不能混在一起：

|诊断|修改内容|观察目标|
|---|---|---|
|样本错配|替换成另一个动作序列不同、但传感器和时长匹配的雷达窗口|是否真正利用雷达内容|
|时间顺序扰动|同步打乱 RD 和 MD 的时间顺序，保留原标签仅作敏感性诊断|是否利用时间顺序|

时间打乱会造成分布外输入，结果下降并不能单独证明模型理解了动作顺序。

更强的顺序测试应从真实数据中寻找 动作集合相同、执行顺序不同 的记录，构造匹配样本对，例如：

`Walk → Sit` 对比 `Sit → Walk`。

如果真实数据里没有足够的反序样本，就如实报告数量不足，不人为编造测试数据。

### 3.4 将动作漏检做结构化分解

现有测试中，148/484 个窗口预测动作数量偏少。

需要进一步回答：到底漏掉了哪些动作，漏检与什么因素有关？

对每个 GT 动作实例记录：

`class_id、duration、relative_start、relative_end、at_window_edge、subject、sensor、environment`。

建议使用以下分桶：

|维度|分桶|
|---|---|
|动作持续时间|小于1秒、1–2秒、2–4秒、大于等于4秒|
|相对窗口位置|开头、中间、结尾|
|是否被窗口截断|完整、左截断、右截断|
|窗口动作数量|1、2、3|
|动作类别|14 类分别统计|

特别区分两种错误：

- 动作漏检： GT 中存在动作，生成中没有对应动作。
    
- 动作识别错误： 模型生成了对应时段的其他动作类别。
    

由于当前短语匹配没有可靠的逐时段对齐，第二项在自动评估中可能无法完全判断，需要人工抽样复核。

最终输出一份错误归因报告，而不是只得到一个更高或更低的整体分数。

### 3.5 本阶段输出

必须交付：

- Stage 1 混淆矩阵与逐类指标。
    
- CNN / GRU / Align 特征线性探针。
    
- 平滑分类模板对照结果。
    
- 无雷达基线及错配诊断。
    
- 按持续时间、窗口位置、类别统计的漏检报告。
    
- 一份结论明确的瓶颈定位报告。
    

进入下一阶段的条件： 已经能够根据实验说明，优先改进 Encoder、跨模态接口还是生成目标。若证据不充分，就保持当前架构，不直接增加新模块。

## 四、Stage 2：扩展数据与建立正式评测协议

这一阶段建议在新增训练之前完成。否则后面每一次改模型都会面临测试结果不可比较的问题。

### 4.1 数据集划分

以你计划使用的24名受试者为基础，先核对 canonical 数据中实际可用的受试者、动作类别、传感器和环境覆盖情况。

如果24名受试者的数据都满足要求，我建议采用：

推荐划分：20 人开发 + 4 人最终测试

20 人 · Development

4 人 · Test

Development：5 折交叉验证，每折16人训练、4人验证。Final Test：所有实验选定后才评测。

必须注意：你之前已经对 subject06 进行了测试分析，旧项目归档中也记录了部分其他受试者被用于开发的情况。

方案书v2.5.md

因此不能任意挑选四名受试者就声称是“从未使用的独立测试集”。

正确流程是：

1. 先审计所有已有实验实际使用过的受试者。
    
2. 从确实未参与过训练、模型选择或错误分析的受试者中选择最终测试组。
    
3. 如果不足四人，就减少最终测试人数，或补充真正独立的记录；不能把已看过结果的受试者重新命名为盲测数据。
    

### 4.2 分组交叉验证

开发集建议使用5折 Group K-Fold，按 `subject_id` 分组。

任何一个受试者的全部录音、两个雷达视图和所有重叠窗口必须属于同一个划分。

划分前尽量平衡各折的类别、传感器和环境分布。若需要分层分组方法，应保证受试者始终是不可拆分的分组单位。

每折使用3个独立种子，例如 17、23、42。它们是新方案的预设配置，不对应此前实验的已完成结果。

但为了控制 RTX 2080 Ti 的计算成本，我建议采用两层实验制度：

|层次|数据与种子|用途|
|---|---|---|
|快速筛选|固定开发划分、1个 seed|排除明显无效的改动|
|正式确认|5折 × 3 seeds|验证优选方案的稳定性|
|最终测试|锁定方法后，训练开发集模型并评测保留测试组|最终泛化结论|

正式确认阶段，基线与改进方法必须使用相同的划分、随机种子和评测协议。

### 4.3 环境和传感器分析

同时报告：

- Homelab 与 Hospital。
    
- 两种雷达视图分别的结果。
    
- 全部数据合并结果。
    
- 每个受试者的结果及分布。
    

这些是分组性能分析。如果某种环境只包含固定的一部分受试者，或者传感器与环境高度绑定，就不能据此声称已经独立验证了跨环境或跨设备泛化。

真正要证明跨环境泛化，应当另设环境留出协议。

### 4.4 统一评价指标

建议建立两层指标体系。

基础动作理解指标：

|指标|优先级|计算含义|
|---|---|---|
|Action Macro-F1|主指标|14类动作分别计算 F1 后宏平均|
|Sequence Exact|主指标|完整动作序列及顺序完全一致|
|Action Recall|关键辅助|衡量动作漏检|
|Action Precision|辅助|衡量多生成与错误动作|
|Order LCS|辅助|保留原 Pilot 的归一化最长公共子序列口径|
|Count Accuracy|辅助|预测动作数与 GT 一致的比例|
|Per-class Recall|诊断|逐类动作召回|

Action Macro-F1 应基于逐窗口动作出现次数匹配定义 TP、FP、FN，再按类别汇总；不能直接把现有逐窗口平均 F1 改名为 Macro-F1。重复同类动作的计数规则也需要固定。

描述生成指标：

可以补充 BLEU、ROUGE-L、METEOR 和 BERTScore，但它们只适合衡量与弱监督参考文本的接近程度。

此外，应抽取固定数量的预测，由人工检查动作正确性、先后关系、遗漏以及有无无证据细节。

当前不应该用这些文本指标证明细粒度人体运动理解能力。

### 4.5 Checkpoint 选优规则

我的建议是：

- Stage 1：以未见验证受试者的逐类 Macro-F1 为主，validation CE 用于监控。
    
- Stage 2：以验证集生成的 Action Macro-F1 为主，Sequence Exact 作为第一平局判据，Action Recall 和 Count Accuracy 作为辅助诊断。
    
- 当 Macro-F1 与 Sequence Exact 发生冲突时，按训练前固定的规则选优，不临时调整权重。
    

冻结规则后，再进行新的训练实验。

对于统计显著性，使用受试者为聚类单位进行配对 bootstrap，报告95%置信区间。两个雷达视图、多个 seed 和重叠窗口都不能直接当成相互独立的受试者重复。

## 五、Stage 3：Radar Encoder 的针对性优化

仅当 Stage 1 的诊断表明编码器或特征表示不足时启动

我不建议一开始就把所有编码器改动全部做完。应按诊断结果选择相应分支。

### 5.1 优化 RD/MD 空间特征保留

这是我认为最值得优先尝试的编码器改进。

现有 CNN 使用：

```
nn.AdaptiveAvgPool2d(1)
```

它保留每个通道的全局响应，但削弱特征在 Range、Doppler 轴上的绝对位置。

建议做三个对照：

|实验|改动|目的|
|---|---|---|
|E0|原始 Global Average Pooling|基线|
|E1|`AdaptiveAvgPool2d((4,4))`|保留粗粒度二维位置|
|E2|RD、MD 按物理轴分别池化|利用两种输入的结构差异|

E2 可以采用更有针对性的处理：

RD CNN

保留粗粒度 Range 与 Doppler 网格

Spatial Features

MD CNN

保留 Doppler 频率位置和局部时间结构

Micro-motion Features

Linear Projection → BiGRU

保持输出维度256不变，避免影响下游接口

注意：不能不区分物理意义，就让 RD 和 MD 简单共享完全一致的池化策略。要先核对实际输入轴顺序。

只有 E1、E2 显示稳定收益后，再尝试 CoordConv 或显式物理属性特征。不要把多种改动同时合并。

### 5.2 归一化实验

建议单独比较：

|方案|方法|
|---|---|
|N0|当前窗口内 Signed-log + Z-score|
|N1|Signed-log 后使用训练集全局统计|
|N2|Signed-log 后使用按传感器分组的训练集统计|

训练集统计必须只在当前折的训练受试者上计算，并且 RD 与 MD 分开统计。

建议额外记录输入原始幅值、能量分布及归一化后的分布，判断床相关动作的弱反射是否被不合理地压缩或放大。

不要预设 N1 或 N2 一定优于 N0。

### 5.3 类别平衡与训练策略

如果诊断表明某些动作明显缺少训练监督，则考虑以下优化。

类别平衡：

优先比较原始 CE 与温和的类别加权 CE。权重可以按训练集类别频率的平方根倒数构造，进行归一化，具体计算规则在运行前固定。

不要直接对少数类别使用极高权重，也不要同时叠加强过采样和强类别权重。

对于时序动作，逐帧类别频率和动作实例频率并不相同，应分别统计后再确定平衡策略。

训练设置：

|参数|建议|
|---|---|
|Optimizer|AdamW|
|Stage 1 初始 LR|保留 $10^{-3}$ 基线|
|最大 Epoch|30–50，作为预算上限|
|Early Stopping|例如连续5轮验证主指标未改善|
|LR Scheduler|作为单独消融项引入 Cosine|
|Grad Clip|1.0|
|Checkpoint|保存验证主指标最佳权重|

30–50 Epoch 不是必须全部跑满。训练到3轮以外是否继续，应根据学习曲线与预设早停规则决定。

数据增强：

第一批只测试最容易控制标签一致性的增强，例如轻微幅度扰动、符合物理尺度的小范围裁剪和时间扰动。

随机裁剪必须同步更新动作标签；时间拉伸必须保持 RD、MD、时间戳及标签一致。距离平移和 Doppler Masking 也需要验证是否破坏动作的物理证据。

### 5.4 是否需要增加时序卷积？

暂时不作为默认修改。

只有当诊断确认：

- CNN 特征可分；
    
- GRU 的逐帧分类存在明显孤立抖动；
    
- 平滑后处理无法充分解决，或者对短动作产生较大损害；
    

才考虑在 BiGRU 后加入轻量 Temporal Conv，并对比是否需要 MS-TCN 风格的截断平滑损失。

先做后处理基线，再引入可学习的时序精修，才能证明新模块的必要性。

### 5.5 Encoder 阶段的验收条件

建议采用以下预注册的候选门槛：

- 相对原始 E0，在相同开发协议下 Action Macro-F1 提升至少2个百分点；
    
- 5折中至少4折不低于原始模型；
    
- 关键床相关动作没有出现无法解释的大幅性能下降；
    
- 短动作召回率至少不明显恶化。
    

这些是建议的工程筛选门槛，不是统计显著性的充分证明。正式结果仍以受试者级配对差值与置信区间为准。

如果改进模型只是降低训练 CE，却没有提升未见受试者性能，则不进入 Stage 2 对齐实验。

## 六、Stage 4：雷达到语言模型的接口优化

当雷达特征具备可分性，但自然语言生成仍明显较差时启动

这一阶段我建议保持 Qwen2.5-0.5B-Instruct 不变，先确定问题是否来自 Radar Tokens、Projector 或语言生成目标。

### 6.1 先对比冻结 Encoder 和联合微调

使用同一个已经训练好的雷达编码器，比较：

|实验|Encoder|Projector|Qwen|
|---|---|---|---|
|A0 原始 Align|训练|训练|冻结|
|A1 Frozen Encoder|冻结|训练|冻结|

两组都从相同的 Stage 1 权重初始化，在相同的数据与训练预算下比较。

这可以回答一个关键问题：

让语言损失反向更新 Radar Encoder，究竟改善了语言生成，还是破坏了已经学到的运动特征？

若 A1 更好，说明优先优化 Projector、减少对雷达编码器的扰动可能更加合理。

若 A0 更好，说明任务相关的端到端特征适配可能确实有价值。

### 6.2 Radar Token 数量消融

现有 K=8，采用固定有序时间平均池化。

建议测试：

|K|12秒输入的平均时间覆盖范围|目的|
|---|---|---|
|4|约3.0秒/Token|强压缩基线|
|8|约1.5秒/Token|当前模型|
|16|约0.75秒/Token|保留更细时间结构|
|32|约0.375秒/Token|高时间分辨率|

这些是平均覆盖范围，不是 Token 的有效感受野；BiGRU 的输出已经包含前后文。

重点不是只看 Sequence Exact 是否提高，而是观察：

- 短动作 Recall。
    
- 三动作窗口 Recall。
    
- Count Accuracy。
    
- 床相关动作召回。
    
- 生成与参考动作数量之差。
    
- 推理显存和计算成本。
    

如果 K=16 已经能够稳定改善短动作识别，而 K=32 收益很小，就没有必要继续增加。

反过来，如果增加 Token 数量没有帮助，不应直接得出“时间信息不足”的结论。

### 6.3 改进语言损失：动作词重点监督

现有模型使用普通的自回归 CE：

$$
\mathcal L_{\text{caption}} =-\frac1N\sum_j\log P(y_j\mid y_{<j},X)
$$

这会监督所有生成 Token，但未专门强调动作类别词。

例如：

`The person walks toward the bed, then sits down on the bed.`

其中有些词是固定模板结构，学习起来比较容易；真正决定描述正确性的动作短语只占其中一部分。

可以增加动作词加权机制：

$$
\mathcal L_{\text{weighted}} = -\frac{\sum_j w_j\log P(y_j\mid y_{<j},X)} {\sum_j w_j}
$$

建议：

$$
w_j= \begin{cases} 2,&\text{动作短语对应的 Token}\\ 1,&\text{其他文本 Token} \end{cases}
$$

动作短语的 Token 范围必须使用 tokenizer 的实际分词结果和文本偏移来确定，不能直接依据英文空格划分。

先比较普通 CE 与动作词加权 CE。权重2是初始实验候选，不代表已经验证最优。

这里仍然使用自然语言描述作为最终输出，而不是把分类目标直接替换成输出数字标签。

### 6.4 增加动作数量监督

这是我认为有针对性、且可以保持架构简单的改进。

你已经观察到大量窗口漏动作。模型可能不只是认错类别，还可能没有形成正确的“应该描述几个动作”的全局判断。

可以在 BiGRU 输出后增加一个轻量 Count Head：

```
BiGRU Hidden States
        │
        ├── Temporal Pooling → Radar Tokens → Projector → LLM
        │
        └── Global Pooling → Count Head → 1 / 2 / 3
```

训练时加入：

$$
\mathcal L_{\text{total}} = \mathcal L_{\text{caption}} +\lambda_{\text{count}}\mathcal L_{\text{count}}
$$

其中：

$$
\mathcal L_{\text{count}} =\operatorname{CE}(\hat n,n_{\text{GT}})
$$

建议先比较 $\lambda_{\text{count}}=0$ 与 $0.1$，然后依据训练前固定的规则决定是否扩大消融。

但需要注意三点：

- 当前单动作窗口太少，必须先改善训练样本分布。
    
- Count GT 来自标签序列，不一定代表精确的物理事件数量。
    
- 推理时先不强制 LLM 生成指定个数，只观察辅助监督是否改善覆盖率。
    

如果 Count Head 数量预测准确，但 LLM 仍然漏动作，那么问题更可能集中在语言解码或对齐，而不是动作数量感知。

### 6.5 加入强符号基线

必须比较两条路线：

路线 A：直接 Radar-to-Text

Radar Encoder → Tokens → Projector → LLM → Caption

路线 B：分类识别后生成

Radar Encoder → Classifier → Smooth → Action List → Caption

路线 B 再分为两个版本：

- B1： 动作列表直接经过固定模板转成自然语言。
    
- B2： 将预测动作列表交给冻结 Qwen，生成自然语言。
    

另外增加一组 Oracle：把真实动作列表交给 Qwen，检查其在已知正确动作顺序时的语言表达能力。

Oracle 是语言后端能力上限诊断，不是使用雷达推理的公平对照。

最终应当回答：

> 在同等评测协议下，直接使用连续 Radar Tokens 生成语言，是否比先识别离散动作、再组织语言更有效？

如果直接生成没有超过平滑分类路径，就需要重新审视其研究价值，不能仅因输出经过 LLM 就认为方法更先进。

### 6.6 最后才考虑 LoRA

只有前面证明雷达信息充分、Projector 训练已经接近瓶颈、而语言生成仍存在稳定的错误之后，才开展 LoRA 消融。

建议先选择：

- Qwen2.5-0.5B-Instruct。
    
- LoRA rank 8 或 16。
    
- 只作用于注意力投影层。
    
- 与冻结 Qwen 使用相同的训练/验证数据和生成指标。
    

RTX 2080 Ti 的显存有限，LoRA 阶段先做实际显存和反向传播预检。

现阶段不推荐扩大到1.5B或7B。 模型容量不是目前已确认的主要瓶颈。

## 七、Stage 5：训练数据与标签优化

这部分与 Stage 3、Stage 4 的改动分开实验，避免把数据收益错误归因于模型结构。

### 7.1 扩充单动作训练样本

首轮训练集：

|动作数量|窗口数|占比|
|---|---|---|
|1|20|0.91%|
|2|582|26.61%|
|3|1585|72.47%|

单动作样本明显不足，但应注意：这主要说明当前12秒窗口采样策略几乎不产生单动作样本，不代表 PARrad 原始数据中只有20个可用单动作实例。

建议从训练受试者的原始录音中重新构造：

单动作短窗口： 选择主要由一种动作构成的有效片段，窗口长度根据真实动作持续时间设置，不强行要求所有动作达到固定时长。

双动作窗口： 覆盖两种动作的完整过渡，尤其增加容易混淆的动作组合。

三动作窗口： 保留现有复杂动作链，不能为了提高单动作比例而大幅减少。

可以将单/双/三动作采样比例设为约20%/40%/40%，作为初始消融候选，而不是事先确定的最佳比例。

实际比例需要根据唯一动作实例数量调整，避免同一个短动作被大量重采样，造成虚假的数据量增长。

### 7.2 特别处理动作窗口边缘

不要直接丢弃所有边缘动作。

建议维护两个训练子集：

|子集|用途|
|---|---|
|Complete Actions|学习完整动作语义，减少模糊标签|
|Partial Actions|学习有限观察条件下的动作描述|

对于 Partial Actions，如果原始标签不足以判断被截断部分，就只监督窗口中可以支持的内容，不要求模型猜测窗口外的动作过程。

在测试时保留原始窗口，并分别计算两类动作的召回。

这样不仅可以提升模型训练质量，还能够分析模型在部分动作可观测条件下的能力边界。

### 7.3 提升床相关动作的覆盖

建议专门检查：

- 床相关动作在训练集中的数量和持续时间。
    
- 不同受试者是否执行方式差异较大。
    
- 不同传感器视图中是否存在明显性能差异。
    
- 与椅子、地面相关动作的混淆关系。
    
- 是否能够从 RD/MD 中识别动作本身，却无法判断动作所涉及的家具或位置。
    

最后一点尤其重要。

如果输入中只有人体运动频谱，缺少足够的空间参照，那么“从床上起身”和“从椅子上起身”可能具有相似的运动表现。

因此，需要把人体动作识别和场景参照识别分开诊断。

如果雷达信号本身不足以可靠区分这些对象，就不能单纯通过增大 CNN 或 LLM 期望解决。应在论文中明确可观测信息的限制。

## 八、完整实验矩阵与执行优先级

为了避免实验数量失控，我建议把实验分成三组：必要诊断、单变量改进、最终确认。

### 8.1 必要诊断实验

|ID|实验|是否重新训练主模型|优先级|
|---|---|---|---|
|D01|原始 Pilot 复现及权重检查|否|P0|
|D02|Stage 1 混淆矩阵、逐类 F1|否|P0|
|D03|CNN/GRU/Align 特征线性探针|只训练轻量探针|P0|
|D04|平滑分类模板基线|否|P0|
|D05|按时长、窗口边缘的漏检分析|否|P0|
|D06|雷达错配、时间扰动|否|P1|
|D07|无雷达语言先验|是，小规模|P1|
|D08|Oracle 动作列表 → Qwen|否|P1|

D01–D05 完成后，就应该进行第一次错误归因评审。

### 8.2 候选改进实验

|ID|实验变量|基准|改进|
|---|---|---|---|
|E01|CNN 空间池化|GAP 1×1|4×4|
|E02|RD/MD 物理轴池化|统一 GAP|分模态池化|
|E03|归一化|每窗口|全局/按传感器|
|E04|类别平衡|普通 CE|温和加权 CE|
|E05|数据采样|原始窗口分布|单/双/三动作均衡|
|A01|对齐时更新 Encoder|联合训练|冻结 Encoder|
|A02|Token 数量|K=8|K=4/16/32|
|A03|文本损失|普通 CE|动作词加权 CE|
|A04|动作覆盖|普通 Caption Loss|Caption + Count Loss|
|A05|LLM 训练|冻结|LoRA|

不要求全部执行。 D01–D08 的结果决定先启动 E 系列还是 A 系列。任何候选改动未通过快速筛选，就不进入高成本多折验证。

### 8.3 最终消融实验

确定最终模型后，至少形成以下对照：

|方法|作用|
|---|---|
|原始分类 → 模板|传统基线|
|分类 → 平滑 → 模板|强分类基线|
|分类 → 平滑 → Qwen|强符号生成基线|
|原始 Radar-to-Text|原始端到端基线|
|Radar-to-Text + 改进模块|验证最终方法|
|改进方法去掉各个新增模块|证明每项改进的独立贡献|

这里的“原始 Radar-to-Text”也需要在新的正式数据划分上重新训练。

## 九、实验推进条件与停止规则

我建议采用明确的决策流程。

完成 Stage 1 错误诊断

雷达特征可分性不足

优化 Encoder / 数据

先看 Macro-F1、混淆矩阵与短动作召回

雷达特征可分，但生成差

优化 Projector / Loss

先看动作覆盖率、接口损失与生成错误

统一开发协议，多折多 seed 验证

比较配对指标、跨受试者稳定性与模块贡献

锁定最终架构 → 独立 Final Test

每项实验都要在运行前固定：

- 主指标、辅助指标及成功条件。
    
- 训练步数或最大 Epoch、早停规则。
    
- 数据划分、随机种子、初始化来源。
    
- 允许修改的变量及禁止修改的部分。
    
- 失败处理与停止条件。
    

实验结束后不因结果接近门槛而临时增加训练轮数、改阈值或更换选优指标。

若想扩展预算，应作为新的实验配置，保留旧结果。

## 十、RTX 2080 Ti 上的实施安排

考虑你当前只有一张 RTX 2080 Ti，我建议按以下顺序执行，而不是并行运行大量训练。

|阶段|工作|建议安排|
|---|---|---|
|第1阶段|旧实验核验、标签/时间对齐审计|1–2天|
|第2阶段|D01–D08 诊断与报告|2–3天|
|第3阶段|完善数据划分、平衡窗口、评测器|2–3天|
|第4阶段|依据诊断进行单变量快速筛选|3–5天|
|第5阶段|优选方案5折×3 seeds正式验证|根据实际吞吐安排|
|第6阶段|锁定模型、最终测试、消融与论文图表|2–3天|

这是建议的工作顺序，不是保证完成时间；24人数据规模、全序列长度和训练轮数增加后，实际 GPU 时间需要重新测量。

建议在开始完整交叉验证前，先做一折的资源预估，记录每 Epoch 时长、显存峰值和温度。正式实验串行执行，避免多进程争用显存，也避免把热节流造成的速度差异误认为架构差异。

## 十一、最终交付标准

这一轮优化结束时，我希望不仅得到一个更高的准确率，还能交付四项有研究价值的成果。

|交付|必须包含|
|---|---|
|数据与协议|可复现的受试者划分、窗口规则、标签检查报告|
|模型与权重|完整配置、初始化来源、最佳 checkpoint、SHA|
|性能结果|按受试者、类别、传感器、环境拆分的指标与置信区间|
|方法分析|关键消融、错误归因、复杂度及代表性生成案例|

在性能上，建议把以下数值当作研究目标，而不是已经有证据保证可以达到的结果：

- 完整序列准确率明显超过同协议下的原始 Radar-to-Text 和平滑分类基线。
    
- Action Macro-F1 有稳定提升，且不能只依靠高频动作带动平均分数。
    
- 床相关类别召回率有改善。
    
- 动作数量偏少的比例下降，同时 Precision 不显著退化。
    
- 真正独立的受试者测试能复现开发阶段的主要结论。
    

即使最终没有达到这些目标，只要错误归因和消融严谨，也能够明确下一步研究瓶颈。

## 十二、最终论文应该如何定位

你现在主要依靠 PARrad 的动作标签构建描述，能够严谨支持的论文主张是：

Offline Continuous Radar-to-Text Action Description with Weak Supervision

即：基于弱监督的离线连续毫米波动作描述。

论文可以重点研究雷达物理结构保持、时序信息压缩、跨模态语义对齐以及多动作描述完整性。

但如果想进一步提出“细粒度自然语言运动描述”，还需要构造或获取具有独立验证依据的运动属性文本标注，例如速度变化、动作持续、停顿或可观察的姿态变化。

不能仅根据标签模板生成的文本质量证明这些能力。

## 十三、现在最应该执行的任务

我建议下一次代码实施只下达一个明确任务：

Radar-to-Text Diagnostic Pack v1

目标： 不修改现有模型、不重新训练 Encoder 或 LLM，复用已保存的 Stage 1 和 Align checkpoint，完成：

- 数据、RD/MD 时间对齐和权重来源核验。
    
- Stage 1 全部14类动作混淆矩阵及逐类 F1。
    
- Stage 1 与 Align 特征的线性可分性诊断。
    
- 原始分类与平滑分类模板对照。
    
- 按持续时间、边缘截断及动作类别的生成漏检分析。
    
- 输出一份明确指出主要瓶颈及后续推荐实验的报告。
    

限制： 不修改源 Pilot 产物，不查看新的最终测试集，不自动开展后续架构训练。
