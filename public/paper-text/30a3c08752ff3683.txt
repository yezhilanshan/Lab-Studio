1 Introduction
The proliferation of Internet of Things (IoT) devices in criti-
cal infrastructure has fundamentally transformed network
security paradigms. Modern IoT ecosystems, encompassing
smart cities, industrial control systems, and electric vehicle
charging stations, generate massive volumes of network traf-
fic requiring real-time security monitoring [1, 2]. However,
the resource-constrained nature of edge devices—charac-
terized by limited computational power, memory capacity,
and energy budgets—presents fundamental challenges for
deploying sophisticated intrusion detection systems (IDS)

Abstract
Distributed IoT systems in critical infrastructure demand intrusion detection solutions that balance detection accuracy
with the computational constraints of edge deployment. This study presents a lightweight Spiking Neural Network (SNN)
framework for network intrusion detection, utilizing the computational properties of spike-based processing — namely,
replacement of multiply-accumulate (MAC) operations with sparse accumulate (AC) operations and input-adaptive com-
putation through natural spike sparsity — to explore neuromorphic-compatible architectures suited to resource-constrained
edge deployment. The framework is validated on the Edge-IIoTset dataset [1] through five-fold stratified cross-validation.
A multi-stage feature selection pipeline reduces the input space from 97 to 35 features (63.9% reduction), including
removal of seven features exhibiting strong target correlation (|r| > 0.70) to promote broader feature diversity. Task-scaled
architectures match network capacity to classification granularity, ranging from 9,342 parameters (36.5 KB) for binary
to 51,347 parameters (200.6 KB) for fifteen-class classification. Cross-validation results show consistent performance:
binary 99.18% (±0.03%), six-class 96.99% (±0.11%), and fifteen-class 96.79% (±0.08%) accuracy. Minority class detec-
tion remains a limitation, with Fingerprinting (54.04%) and Password (59.46%) recall indicating challenges from class
imbalance and feature overlap. These results suggest that compact spiking architectures can provide effective intrusion
detection within the memory budgets of edge processors, establishing architectural groundwork for future neuromorphic
deployment.

Spiking Neural Networks (SNNs) offer a computation-
ally distinct alternative to conventional artificial neural net-
works (ANNs). In standard ANNs, each neuron computes a
weighted sum followed by a nonlinear activation — requir-
ing multiply-accumulate (MAC) operations proportional to
the number of input connections at every inference step. In
contrast, SNNs communicate through binary spike events: a
presynaptic neuron either fires (1) or remains silent (0), and
postsynaptic computation occurs only when a spike arrives.
This replaces dense MAC operations with sparse accumu-
late (AC) operations, where synaptic weights are added to
the membrane potential only upon spike arrival [8]. The
computational cost of SNN inference is therefore data-
dependent: inputs that produce fewer spikes (i.e., features
with lower normalized values under Poisson rate coding)
naturally consume fewer operations, creating an implicit
compute-on-demand mechanism.
This property is particularly relevant for IoT intrusion
detection, where network traffic features exhibit high vari-
ability — normal traffic typically produces sparse feature
vectors, while attack traffic activates specific feature sub-
sets. An SNN processing such inputs will allocate more
computation to anomalous patterns and less to routine traf-
fic, without requiring explicit gating mechanisms. Further-
more, the binary nature of spike communication reduces the
memory bandwidth requirements during inference, as spike
events can be represented as single bits rather than 32-bit
floating-point activations [9, 10].
While the full energy benefits of SNNs are realized on
neuromorphic hardware platforms such as Intel’s Loihi [9]
and IBM’s TrueNorth [10], the computational advantages
of spike sparsity and accumulate-only operations are archi-
tecture-independent properties that hold on any platform.
The present study investigates the feasibility and detection
accuracy of SNN-based intrusion detection within edge-
compatible parameter budgets, establishing the architectural
groundwork for future neuromorphic deployment.
1.1 Research motivation
This study is motivated by three interconnected challenges
in IoT security. First, we aim to reduce feature dimensional-
ity while maintaining detection performance. Starting from
the preprocessed dataset [1] (97 features), we apply a multi-
stage selection pipeline combining variance filtering, inter-
feature correlation analysis, statistical ranking, and target
correlation filtering to produce a compact 35-feature rep-
resentation that retains detection capability while reducing
input dimensionality by 63.9%.
Second, we investigate whether SNN architectures can
maintain detection accuracy within the parameter and
memory budgets of edge processors while exploiting the
computational properties inherent to spike-based process-
ing. Conventional ANNs require dense MAC operations
at every layer regardless of input characteristics; SNNs,
by contrast, perform computation only upon spike arrival,
with the volume of computation scaling naturally with input
activity. This study systematically explores how compact
SNN architectures (9,342–51,347 parameters) perform
across three classification granularities, establishing base-
line feasibility for neuromorphic-ready intrusion detection
at the edge.
Third, we emphasize statistical validation to ensure reli-
able performance estimates. We employ five-fold strati-
fied cross-validation with fixed random seeds to quantify
expected variance across data partitions, providing a trans-
parent assessment of model consistency for deployment
reliability.
1.2 Research contributions
This study makes three principal contributions to IoT intru-
sion detection research:
First, we apply a multi-stage feature selection pipeline
on the preprocessed dataset [1], combining variance filter-
ing, inter-feature correlation filtering, ANOVA F-test rank-
ing, and target correlation filtering (|r| > 0.70) to produce
a compact 35-feature representation. This achieves 96.79%
fifteen-class accuracy with 63.9% fewer features.
Second, we develop a task-scaled SNN architecture that
matches network capacity to classification granularity, rang-
ing from 9,342 parameters (36.5 KB) for binary to 51,347
parameters (200.6 KB) for fifteen-class classification. All
configurations use a uniform Linear → LIF processing pipe-
line, where inference computation scales with spike activity
rather than network size. This neuromorphic-ready design
enables direct deployment on spike-based processors with-
out architectural modification.
Third, we conduct five-fold stratified cross-validation
with fixed random seeds (seed=42) across binary, six-class,
and fifteen-class classification scenarios. All experimental
protocols, including data preprocessing steps, feature selec-
tion criteria, and cross-validation procedures, are docu-
mented in detail to facilitate reproducibility.

2 Related work
The application of machine learning to IoT intrusion detec-
tion has evolved significantly in recent years, with research-
ers exploring various architectures and methodologies to
address the dual challenges of detection accuracy and com-
putational efficiency.
2.1 Deep learning for IoT intrusion detection
Deep learning architectures have demonstrated strong per-
formance on IoT security benchmarks. Ferrag et al. [2] pro-
vided a comprehensive survey of deep learning techniques
for intrusion detection in IoT environments, highlighting the
effectiveness of convolutional neural networks (CNNs) and
recurrent architectures for temporal pattern recognition.
Kilichev et al. [1] developed a CNN-LSTM-GRU
ensemble architecture on the Edge-IIoTset dataset, achiev-
ing 100% binary, 97.44% six-class, and 96.90% fifteen-
class accuracy.
Their approach employed chi-squared testing for system-
atic feature engineering, producing a research-ready prepro-
cessed dataset. The published preprocessed dataset contains
97 features after excluding target and label columns.
ElKashlan et al. [3, 4] explored machine learning
approaches for electric vehicle charging station (EVCS)
intrusion detection using the IoT-23 dataset, investigat-
ing filtered classifiers and decision tables for DDoS detec-
tion [3], and extending to multi-class scenarios with Naive
Bayes, J48, and attribute selection classifiers [4].
Nandanwar and Katarya [5–7, 11–13] presented a series
of studies addressing IoT security through multiple per-
spectives, including optimized intrusion detection using
GAO-XGBoost with blockchain framework [5], deep learn-
ing for Industrial IoT [6], privacy-preserving data sharing
[7], explainable AI for cyber-physical systems [11], hybrid
blockchain frameworks for IDS [12], and federated learning
approaches [13].
2.2 Feature engineering
Feature selection plays a critical role in intrusion detection
performance, particularly for resource-constrained deploy-
ments. Traditional approaches have employed chi-squared
testing [1], information gain [14], and mutual information
[15] to identify discriminative features. The Edge-IIoTset
dataset [16] provides a comprehensive collection of net-
work traffic from various IoT devices under different attack
scenarios, including DDoS, injection, scanning, MITM, and
malware attacks. In this study, we apply correlation-based
feature analysis (r>0.70) on the preprocessed dataset (97
features) provided by Kilichev et al. [1] to produce a com-
pact 35-feature representation.
To provide context for our methodological choices
described in Sect. 3.2, we present a preliminary analysis
of correlation threshold sensitivity and feature selection
method comparison.
This threshold is supported by established statistical
guidelines: Dormann et al. [17] identify |r| > 0.7 as the point
beyond which collinearity among predictors distorts model
estimation. Ratner [18] classifies correlations above 0.70
as strong. In our pipeline, the inter-feature correlation filter
(Stage 2, |r| > 0.95) addresses predictor collinearity, while
the target correlation filter (Stage 4, |r| > 0.70) removes
encoded categorical variables that carry disproportionately
concentrated discriminative power, reducing the model’s
reliance on a narrow feature subset for edge deployment
robustness. Pearson correlation provides a transparent,
reproducible metric with low computational cost. To vali-
date the threshold selection empirically, we conducted a
systematic sensitivity analysis evaluating five correlation
thresholds on the binary classification task with 5-fold strat-
ified cross-validation. Table 1 presents the results.
The results reveal a clear pattern: thresholds at 0.80
and above retain features that yield near-perfect accuracy
(99.99%). The accuracy plateau at 99.99% for thresh-
olds≥0.80 reflects the well-documented tendency of cate-
gorical encodings to produce high mutual information with
the target when category distributions are class-dependent
[19]. This property makes such features highly effective
for maximum-accuracy objectives — as demonstrated
by Kilichev et al. [1] — but introduces a dependency on
protocol-type metadata that may not generalize across net-
work configurations where protocol distributions differ. Our
threshold selection at 0.70 trades this concentrated discrimi-
native signal for broader feature diversity, balancing dimen-
sionality reduction with detection performance for the target
edge deployment scenario.

2.4 Validation methodology
The choice of validation protocol depends on the research
question. Architecture comparison studies typically employ
a single train-test split to control for partition effects when
comparing multiple models under identical conditions —
an approach that prioritizes internal validity [28, 29]. For
instance, Kilichev et al. [1] evaluated CNN, LSTM, GRU,
and their ensemble on identical partitions, where single-split
evaluation is the appropriate protocol to ensure that observed
performance differences reflect architectural choices rather
than data sampling variation.
Deployment-oriented studies, by contrast, benefit from
cross-validation to quantify expected variance across
unseen data partitions — prioritizing external validity [30].
Stratified k-fold cross-validation preserves class distribu-
tions across folds, which is particularly important for imbal-
anced datasets common in intrusion detection [31]. Since
the present study focuses on deployment reliability rather
than architecture comparison, we adopt five-fold stratified
fair comparison—on the fifteen-class classification task.
Table 2 presents the results.
All four methods achieve comparable accuracy within
a 0.09% point range (96.77–96.86%), confirming that the
Edge-IIoTset feature space is robust to the choice of selec-
tion method. Correlation-based filtering was selected for
two reasons: (1) it is the only method that can explicitly
identify features with high target correlation, enabling
detection and removal of features with disproportionately
concentrated class-discriminative power as demonstrated in
Table 1; and (2) correlation coefficients provide transpar-
ent, reproducible metrics with clear physical interpretation,
which is important for deployment in security-critical IoT
environments.
2.3 Spiking neural networks
Spiking Neural Networks (SNNs) process information
through discrete spike events rather than continuous-
valued activations, potentially enabling energy-efficient
computation on neuromorphic hardware platforms such
as Intel’s Loihi and IBM’s TrueNorth [9, 10]. Tavanaei et
al. [8] surveyed SNN learning algorithms, discussing both
biologically-inspired STDP rules and gradient-based train-
ing approaches. Kim et al. [20] explored CNNs for network
intrusion detection on the NSL-KDD dataset, demonstrating
competitive accuracy with reduced computational require-
ments. Wang et al. [21] investigated a lightweight intrusion
detection method for IoT using deep learning combined
with dynamic quantization to reduce computational burden
on edge devices.
Several recent studies have specifically applied SNNs
to intrusion detection. Zhou and Li [22] presented one of
the earliest pure SNN implementations for network intru-
sion detection, employing single-spike temporal coding
with a three-layer architecture of 205 neurons and achiev-
ing 98.98% accuracy on NSL-KDD. Zarzoor et al. [23] pro-
posed IDS-SNNDT, combining a decision tree for sample
selection with a non-leaky integrate-and-fire SNN model
for IoT attack classification, demonstrating reduced latency
and power usage compared to conventional DNN-based
detection. Živadinović et al. [24] investigated resource-effi-
cient SNN-based intrusion detection on the BoT-IoT data-
set, comparing SNN performance against DNN baselines
with focus on computational efficiency. Wang et al. [25]

3.2 Feature engineering
Starting from the preprocessed dataset [1], we apply a
multi-stage feature selection pipeline to produce a compact
feature set suitable for resource-constrained edge devices.
After excluding target and label columns, the dataset con-
tains 97 features spanning network protocol attributes (TCP,
UDP, ICMP, HTTP, DNS, MQTT, Modbus TCP) and their
encoded representations.
The feature selection proceeds in four stages. In the first
stage, features with variance below 0.01 are removed using
a variance threshold filter. This eliminates near-constant
features that carry minimal discriminative information.
In the second stage, pairwise Pearson correlation coef-
ficients are computed among remaining features. For each
pair exhibiting |r| > 0.95, one feature is removed to reduce
redundancy among features measuring similar network
characteristics.
In the third stage, remaining features are ranked using the
ANOVA F-test [32], which measures the ratio of between-
class variance to within-class variance for each feature.
Features with the highest F-statistics are retained, selecting
those that exhibit the greatest separation among classifica-
tion categories. After Stages 1–3, 42 features remain.
In the fourth stage, Pearson correlation coefficients were
computed between each retained feature and the target
labels. Seven features exceeding |r| > 0.70 were identified
and removed: dns_encoded (|r| = 0.95), mqtt1_0, mqtt2_0,
mqtt3_0 (|r| = 0.90 each), mqtt1_encoded, mqtt2_encoded,

Vi (t) = βVi (t − 1) + Ii (t) (2)

3.3 Spike encoding
To interface continuous network traffic features with the
SNN, Poisson Rate Coding is employed. Each input feature
is normalized to the [0,1] range using Min-Max scaling as
described in Sect. 3.1. The normalized value is then inter-
preted as a firing probability at each time step. At each of
the T=50 discrete time steps, a Bernoulli trial is performed
independently for each feature, generating a binary spike
train [t] ∈ {0, 1}. This produces a three-dimensional input
tensor of shape (T × B × F), where B is the batch size and
F=35 is the number of features. Features with higher nor-
malized values produce more spikes on average, preserv-
ing the information content in a spike-based representation.
The simulation length T=50 is selected as a standard value
commonly adopted in surrogate gradient-based SNN train-
ing [33]. This duration provides sufficient spike statistics for
Poisson rate coding while maintaining reasonable computa-
tional cost.

5 Discussion
The experimental results demonstrate that lightweight spik-
ing neural networks achieve competitive intrusion detec-
tion performance across all three classification scenarios
while remaining within memory budgets of typical edge
processors.
It is important to note that the feature selection pipeline
in this study serves a different and complementary purpose
to the chi-squared feature engineering performed by Kili-
chev et al. [1]. Their preprocessing pipeline was designed
to produce a general-purpose, research-ready dataset from
the raw Edge-IIoTset, and it has proven highly effective for
that purpose—serving as a reliable foundation for down-
stream research including the present study. Our additional
correlation-based filtering is specifically motivated by the
constraints of edge deployment, where minimizing input
dimensionality directly translates to reduced memory and
computation at inference time. The encoded protocol fea-
tures removed in Stage 4 (e.g., dns_encoded, mqtt variants)
carry strong discriminative information and are entirely
appropriate for use in server-side or cloud-based detection
systems; their removal here reflects deployment-specific
optimization rather than a limitation of the original data-
set preparation. Indeed, the high discriminative quality of
these features in the preprocessed dataset [1] validates the
effectiveness of the original encoding decisions and pro-
vides downstream researchers with flexibility to select fea-
tures appropriate to their specific deployment requirements.
Moreover, the fact that removing these seven high-leverage
features results in only a 0.11-percentage-point decrease in
fifteen-class accuracy suggests that the preprocessed dataset
[1] contains broadly distributed discriminative information
rather than concentrating predictive power in a narrow fea-
ture subset—a property that enhances its value as a general-
purpose research resource.
It is worth emphasizing that this validation is not merely
qualitative: the near-perfect accuracy achievable with these
categories, making it inherently harder to distinguish with
the current 35-feature set.
The confusion patterns reflect semantic similarity among
attack types. The largest confusion cluster involves Pass-
word, SQL_injection, and Uploading, where shared payload
delivery and data exfiltration characteristics cause signifi-
cant cross-misclassification. DDoS_HTTP shows confusion
with Vulnerability_scanner (660 samples) and XSS (4,099
samples), reflecting overlapping HTTP-based traffic charac-
teristics. DDoS_TCP shows confusion with Port_Scanning
(3,321 samples) due to similar connection-oriented prob-
ing behaviors. Ransomware shows primary confusion with
Backdoor (992 samples), while Backdoor is misclassified as
DDoS_TCP (451 samples) Fig. 7.
Figures 8 and 9 present learning curves. Validation accu-
racy exceeds 92% within the first five epochs across all
folds. The convergence pattern is consistent with the binary
and six-class results, with validation accuracy tracking
training accuracy closely.

5.1 Limitations
This study has several limitations. Evaluation relies on a
single dataset (Edge-IIoTset). Cross-dataset validation on
IoT-23, UNSW-NB15, and CIC-IDS2017 would provide
stronger evidence of generalization across different network
environments and attack distributions.
The study focuses on network-level features. Incorpo-
rating host-based and application-layer indicators could
improve detection of attacks that are not well-characterized
by network traffic alone.
Energy consumption analysis in this study is limited to
algorithmic-level metrics (parameter counts, model memory
footprint, and theoretical operation reduction through spike
sparsity). While these metrics establish compatibility with
edge processor budgets and provide a theoretical basis for
computational efficiency, actual power consumption on neu-
romorphic hardware depends on platform-specific factors
including spike routing overhead, memory access patterns,
and neuron update costs. Hardware-level benchmarking on
platforms such as Intel Loihi 2 or SynSense Xylo is required
to quantify realized energy savings and represents a primary
direction for future work.
Adversarial robustness has not been evaluated. The sen-
sitivity of the SNN to adversarial perturbations in network
traffic features remains an open question. A direct compari-
son between the proposed SNN and an equivalent-capacity
conventional ANN was not conducted. Such ablation would
isolate the contribution of spiking dynamics from the archi-
tectural design and is recommended for future work.
Minority class performance (Fingerprinting: 54.04%,
Password: 59.46%) indicates that class imbalance poses
a challenge that the current architecture does not fully
address. Analysis of the confusion matrix reveals two dis-
tinct root causes: (1) sample scarcity, where Fingerprinting
(853 samples, 0.04% of the dataset) lacks sufficient repre-
sentation for the model to learn discriminative patterns; and
(2) feature overlap, where Password (49,933 samples) and
SQL_injection (50,826 samples) share overlapping feature
distributions despite moderate sample counts, with 17,199
Password samples misclassified as SQL_injection and
11,910 SQL_injection samples misclassified as Password.
To quantify the potential for improvement, we evalu-
ated three class imbalance mitigation strategies on the
dimensionality (97 vs. 35), and model capacity, this mar-
gin does not support a meaningful performance distinction
between the two approaches.
Third, the precision-recall balance in binary classifica-
tion (99.97% precision, 97.09% recall) reflects a conserva-
tive detection strategy.
Fourth, confusion matrices across all scenarios reveal
that misclassifications primarily occur between semanti-
cally related attack types — Password with SQL_injection
and Uploading, DDoS_HTTP with Vulnerability_scanner
and XSS, DDoS_TCP with Port_Scanning.
Fifth, per-class performance in fifteen-class classifica-
tion generally correlates with class frequency. High-volume
classes (Normal, DDoS_UDP, DDoS_ICMP) achieve>99%
recall, while minority and semantically overlapping classes
(Fingerprinting: 54.04%, Password: 59.46%, SQL_injec-
tion: 76.53%) show lower performance. Addressing this
through techniques such as SMOTE or cost-sensitive learn-
ing is a direction for future work. The weighted-averaged
metrics reported in Tables 5 and 7 reflect class-frequency
weighting, which is influenced by the dominant Normal class
(71.9% of samples). Macro-averaged metrics, which weight
all classes equally, are lower (six-class: 92.39% precision,
88.68% recall, 89.39% F1; fifteen-class: 87.49% precision,
86.38% recall, 86.57% F1), confirming that minority class
performance remains the primary area for improvement.
The cross-fold standard deviations remain low across
all scenarios (accuracy: ±0.03–0.08%, F1-score: ±0.06–
0.17%), indicating consistent performance across different
data partitions. This consistency is maintained from binary
through fifteen-class classification.

Using the preprocessed dataset [1], we applied a multi-stage
feature selection pipeline to produce a compact 35-feature
representation and developed task-scaled SNN architectures
for three classification scenarios.
The main findings are as follows. Binary classification
achieves 99.18% accuracy (±0.03%), six-class 96.99%
(±0.11%), and fifteen-class 96.79% (±0.08%), with model
sizes ranging from 36.5 KB to 200.6 KB. The 63.9% feature
reduction (97 → 35 features) maintains 96.79% fifteen-class
accuracy. Five-fold stratified cross-validation confirms con-
sistent performance across data partitions.
These results suggest two practical implications for IoT
security deployment. First, correlation-based feature reduc-
tion can substantially decrease input dimensionality without
significant accuracy loss, reducing both memory and com-
putation requirements at the edge. Second, the task-scaled
architecture demonstrates that a single design paradigm
(Linear → LIF) can serve multiple classification granulari-
ties, with inference computation that scales with input spike
activity rather than fixed network size. This allows network
operators to select the appropriate complexity level based on
available device resources, while benefiting from the inher-
ent computational efficiency of spike-based processing.
Future work should address the limitations identified in
this study: cross-dataset validation on IoT-23, UNSW-NB15,
and CIC-IDS2017 to assess generalization, neuromorphic
hardware deployment for actual energy measurements,
adversarial robustness evaluation, class imbalance mitiga-
tion for minority attack types such as Fingerprinting and
Password, and federated learning integration for distributed
IoT security.
